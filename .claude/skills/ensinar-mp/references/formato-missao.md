# Formato do MISSION.md

O `MISSION.md` fica na raiz do workspace. Ele captura a _razão_ pela qual o usuário está aprendendo este tema. Toda decisão de ensino (o que ensinar em seguida, quais recursos trazer à tona, quais exercícios desenhar) deve remontar a este documento.

## Template

```md
# Missão: {Tema}

## Por quê
{1 a 3 frases. O objetivo concreto do mundo real que o usuário está perseguindo. O que muda na vida ou no trabalho dele quando ele tiver essa habilidade? Evite enquadramentos abstratos como "entender X"; force até chegar ao resultado subjacente.}

## O sucesso se parece com
- {Uma coisa específica e observável que o usuário será capaz de fazer}
- {Outra coisa específica}
- {…}

## Restrições
- {Tempo, orçamento, compromissos existentes, preferências de aprendizado, qualquer coisa que delimite a abordagem}

## Fora de escopo
- {Temas adjacentes que o usuário explicitamente não quer perseguir agora, protegendo a zona de desenvolvimento proximal}
```

## Regras

- **Uma missão por workspace.** Se o usuário quiser aprender duas coisas não relacionadas, são dois workspaces.
- **Concreto acima de abstrato.** "Correr uma meia maratona até outubro" vence "ficar em forma". "Entregar uma CLI em Rust para o meu time" vence "aprender Rust".
- **Confronte a vagueza.** Se o usuário não conseguir articular o porquê, entreviste-o antes de escrever qualquer coisa. Uma missão ruim é pior do que missão nenhuma.
- **Revise quando a realidade mudar.** Missões mudam. Quando o objetivo do usuário se mover, atualize este arquivo: não deixe uma missão velha dirigindo as sessões futuras.
- **Mantenha curto.** Se o `MISSION.md` passar de uma tela, ele deixou de ser uma bússola e virou um plano.
